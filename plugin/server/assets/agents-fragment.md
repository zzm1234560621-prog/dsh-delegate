# 本机分工：简单任务派给 DSH，难任务自己做

这台机器上除了你，还有第二套执行环境 **DeepSeek Harness（DSH）**：便宜、能读文件、能跑命令的子代理。默认按下面的分工干活，不要把所有活都自己扛。

## 派给 DSH

- MCP 工具：`dsh_task`（单发）/ `dsh_parallel`（并行）/ `dsh_job`（追长任务）
- 命令行：`dsh --profile headless`（任务从 stdin 或参数传入）

适合派：机械重复（批量改文件/替换/重命名/格式化）、生成小件（命令、正则、脚本、SQL、最小复现）、解释查证（代码在干什么、报错什么意思、参数怎么写）、跑检查并汇总、试错探路。

## 自己做，不要派

需要本轮对话上下文或来回澄清的；跨文件设计改动、架构取舍、要写方案或做判断的；需要逐行审阅的大 diff；凭据、安全、不可逆操作。

判断标准：**能不能用一段自包含的文字说清楚，而且做完不需要你反复拿主意。** 能就派，不能自己做。

## 长任务：job id 不是失败

DSH 跑真活要几分钟，宿主可能等不了。`dsh_task` 最多等 45s：没完成会返回 `job=dsh-xxxx`，那不是失败；接着用 `dsh_job({job_id})` 轮询到 `state=done`。也会一开始就 `mode:"async"` 立刻拿 id。轮询期间不要重复派同一个任务。

## 能并行就并行

2 件以上互不依赖的活一次派出去。每个子代理**能读整个仓库**（相互查看），但只能写自己那块 —— 给每个任务一个 `write_scope`（相对 cwd 的已存在子目录），越界写会被沙箱拒绝。要改同一批文件就串行，或各用 git worktree。默认不限制并发，一次全放出去；任务特别多时注意内存。

命令行并行时把各自 cwd 设成自己的目录，就是各自的写边界：

```powershell
$tasks = @(
  @{ dir = 'src/a'; task = '只改当前目录下的实现……' },
  @{ dir = 'src/b'; task = '只改当前目录下的实现……' }
)
$jobs = $tasks | ForEach-Object {
  $d = $_.dir; $t = $_.task
  Start-Job { param($d, $t) Set-Location $d; $t | dsh --profile headless } -ArgumentList $d, $t
}
$jobs | Wait-Job | Receive-Job
```

## 派活的四条硬规矩

1. 说明必须自包含 —— 它看不到这段对话。
2. 一次一件，或写成编号清单一次跑完；同类小活合并，别反复起进程。
3. 它无人值守（`--approval-policy never`），决策点要提前写死。
4. stdout 就是最终答复；退出码非 0 时看 stderr 里 `dsh:` 开头的行。

## 拿回来怎么用

把它当草稿而不是成品：看 `git diff`、自己跑一遍测试再采用。它报「通过」不等于通过。失败就把具体错误贴进下一次任务描述，别原样重试。
