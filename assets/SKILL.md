# 把简单任务派给 DSH

本机装了 DeepSeek Harness（`dsh`），它能开独立子代理完成整件活：读文件、跑命令、改代码，然后把结论交回来。它看不到我们这段对话，只看到你写下的任务说明。

默认分工：**简单、自包含的活派出去；难的、要拿主意、要你亲自审的活自己留下。**

## 值得派的活

- **机械重复**：按规则批量改文件、批量替换、批量重命名、统一格式
- **生成小件**：一条命令、一个正则、一段脚本、一条 SQL、一个最小复现
- **解释查证**：这段代码在干什么、这个报错什么意思、某条命令的参数怎么写
- **跑检查汇总**：跑测试 / lint / 构建，回报结论和关键输出
- **试错探索**：先让它试几条路，拿到结果再决定方向

## 不该派的活

- 需要本轮对话的上下文，或需要来回澄清的
- 跨文件的设计改动、架构取舍、要写方案或做判断的
- 需要逐行审阅的大 diff 重构
- 凭据、安全、不可逆的操作

## 两种调用方式

**有 MCP 工具时（推荐）**：`dsh_task` 单发、`dsh_parallel` 并行、`dsh_job` 追长任务。

**只有 shell 时**：命令行入口是 `dsh --profile headless`。

```powershell
$task = @'
目标：把 src/ 下所有 .js 的双引号字符串改成单引号，跳过模板字符串。
范围：只改 src/。
完成标准：跑 npx eslint src 通过，报告改了哪些文件。
'@
$task | dsh --profile headless
```

## 长任务：不要被超时骗了

DSH 跑一件真活可能要几分钟，而宿主客户端往往等不了那么久。所以：

1. `dsh_task` 最多等 `soft_wait_ms`（默认 45s）。这之内完成 → 直接给答复。
2. 没完成 → 返回一行 `[DSH 运行中 · 40.2s · job=dsh-xxxx]`。**这不是失败**，只是还没跑完。
3. 用 `dsh_job({ job_id: "dsh-xxxx" })` 继续等（每次最多再等 45s），直到 `state=done/failed`。
4. 也可以一开始就 `mode: "async"`，立刻拿 job id，然后专心轮询。
5. 跑错了或不要了：`dsh_job({ job_id, action: "cancel" })`。

单次调用最多等 50s（`soft_wait_ms` / `wait_ms` 再大也按 50s 算）：调用超过宿主的超时，宿主会重连并重启 dsh-delegate，正在跑的子代理随之被终止。别指望一次等完，多轮询几次。重启过也照样用 `dsh_job` 查原来的 job id：已完成的结果从运行记录里找回，被打断的报「已中断」。

轮询期间不要重复派同一个任务 —— 那会开一堆重复的子代理。

## 并行：一次多个子代理

有 2 件以上互不依赖的活，就并行派，别排队。三条前提：

1. **写范围互不重叠**：每个子代理都能读整个仓库（所以能相互查看），但只能写自己的目录。给每个任务一个 `write_scope`（相对 cwd 的已存在子目录），沙箱把写边界收缩到那里，越界写会被拒绝。
2. **每件活都能独立说清**，不依赖另一件的结果。
3. **粒度别太碎**：每个子代理启动要几秒到几十秒；默认不限制并发，任务特别多时注意机器内存。

```
dsh_parallel({ tasks: [
  { title: "改 a 模块", write_scope: "src/a", task: "只改当前目录下的实现……" },
  { title: "改 b 模块", write_scope: "src/b", task: "只改当前目录下的实现……" }
], max_concurrency: 2 })
```

命令行并行时，把各自 cwd 设成自己的目录，就是各自的写边界：

```powershell
$tasks = @(
  @{ dir = 'src/a'; task = '只改当前目录下的实现……' },
  @{ dir = 'src/b'; task = '只改当前目录下的实现……' }
)
$jobs = $tasks | ForEach-Object {
  $d = $_.dir; $t = $_.task
  Start-Job { param($d, $t) Set-Location $d; $t | dsh --profile headless } -ArgumentList $d, $t
}
$jobs | Wait-Job | Receive-Job
```

**写边界的真实行为**（实测）：

| 动作 | 结果 |
|---|---|
| 读 `write_scope` 之外的任意文件 | 允许 |
| 文件写入工具写 scope 之外 | 拒绝：`[sandbox: file access denied under workspace-write mode]` |
| pwsh / bash 写 scope 之外 | 拒绝（ACL / E_ACCESSDENIED） |
| 写 `%TEMP%`（系统临时目录） | **永远允许** —— 别拿临时目录当仓库测作用域 |

子代理不能 `git commit`（写 `.git` 越界），提交由上层做。要并行改同一批文件，给每个任务一个自己的 git worktree，否则串行。

## 写任务说明的要点

- **自包含**：目标、范围（哪些文件/目录）、约束、完成标准、要回报什么。
- **决策点提前写死**：它无人值守，不会反问；默认值、优先级、不确定时怎么办都要写明。
- **一次一件，或一个清单**：多件事拆开或写成编号清单。
- **合并同类**：启动开销几秒到几十秒，别为了一句话反复起进程。

## 拿回来怎么用

把它当**草稿**，不是成品：看 `git diff`、自己跑一遍测试，再决定采用。它报「通过」不等于通过。失败就把 stderr 里的具体错误贴进下一次任务描述，别原样重试。
